%%% Locks

  \frame{\signpost{2}}

  \frame{
    \frametitle{Mutual exclusion}
    One key. Whoever holds it gets the resource; everyone else waits.
    \diagram[0.9]{figs/mutex.tikz}
  }
  \frame{
    \frametitle{Mutual exclusion}
    This works! It's simple, it's general, and your debugger understands it.
  }
  \frame{
    \frametitle{Mutual exclusion}
    Importantly, this enforces \blueite{serialization}.
    \diagram[0.9]{figs/mutex.tikz}
  }
  \frame{
    \frametitle{Coarse}
    One lock for the whole tree
    \begin{center}\scalebox{0.8}{\contentiontree}\end{center}
  }
  \frame{
    \frametitle{Coarse}
    Correct, and easy.
    \begin{itemize}
      \item<2 -> Also: every operation now waits for every other, even the
                 ones touching opposite ends of the tree
    \end{itemize}
  }
  \frame{
    \frametitle{Fine}
    A lock per node
    \begin{center}\scalebox{0.8}{\contentiontree[all locks]}\end{center}
  }
  \frame{
    \frametitle{Fine}
    Now we get parallelism!
    \begin{itemize}
      \item<2 -> \dots and a locking \blueite{order} to remember
      \item<3 -> \dots and hand-over-hand acquisition on the way down
      \item<4 -> \dots and a plan for when \texttt{f1} holds the left child,
                 wants the right, and \texttt{f2} is doing the opposite
    \end{itemize}
  }
  \frame{
    \frametitle{The usual suspects}
    \begin{enumerate}
      \item<2 -> \blueite{Deadlock}: two of us, each waiting on the other
      \item<3 -> \blueite{Convoying}: the holder gets descheduled, and the
                 whole queue idles until it's back
      \item<4 -> \blueite{Priority inversion}: a low-priority holder keeps a
                 high-priority waiter waiting
    \end{enumerate}
  }
  \frame{
    \frametitle{Lock-free}
    The hardware offers an escape hatch: single instructions that read,
    check, and write \blueite{indivisibly}.
    \begin{itemize}
      \item<2 -> compare-and-swap, load-linked/store-conditional, \dots
    \end{itemize}
  }
  \frame{
    \frametitle{Lock-free}
    A preempted thread can't block anyone, and there's no lock to deadlock on.
    \begin{itemize}
      \item<2 -> but it's \blueite{one word} at a time
      \item<3 -> and every data structure becomes a research paper
    \end{itemize}
  }
  \begin{frame}[fragile]
    \frametitle{Atomic Operations}
    \begin{itemize}
      \item Hardware-supported \emph{indivisible} operations on memory
    \end{itemize}
    \vspace{1em}
    \begin{codeblock}[language=C,basicstyle=\ttfamily\footnotesize]
void atomic_max(atomic_int *target, int val) {

  int current = atomic_load(target);
  while (value > current) {
    if (atomic_compare_exchange_weak(target, &current, value)) {
      break;
    }
  }
}
    \end{codeblock}
  \end{frame}

  \frame{
    \frametitle{Atomic Truth Bombs}
    \begin{itemize}
      \item<2 -> This is awesome!
      \item<3 -> Only works on small amounts of memory (often small-N\# of machine words)
      \item<4 -> Reality: Data-structure often large-N\# of machine words
      \item<5 -> Therefore, getting lock-free data structures right is very hard!
    \end{itemize}
  }
  \frame{
    \frametitle{Pick your poison}
    \diagram[0.85]{figs/considerations.tikz}
  }
  \frame{
    \frametitle{What do we want? (part 2)}
    \begin{enumerate}
      \item<2 -> the \blueite{generality} of locks: any structure, any
                 number of words
      \item<3 -> the \blueite{progress} of lock-free: no deadlocks, no convoys
      \item<4 -> the \blueite{mental model} of neither: just say what must
                 be atomic
    \end{enumerate}
  }

  \frame{
    \frametitle{The dream}
    No keys, no order, no hand-over-hand. Just a bracket around the steps
    that belong together.
  }
  \frame{
    \frametitle{Two blocks, one structure}
    \diagram[0.8]{figs/atomic-blocks.tikz}
  }
  \frame{
    \frametitle{The promise}
    Each atomic block appears to run
    \begin{enumerate}
      \item<2 -> \blueite{all at once}
      \item<3 -> at \blueite{some instant} between its first step and its last
      \item<4 -> with nothing from any other block in between
    \end{enumerate}
  }
  \frame{
    \frametitle{Linearizability}
    So however the blocks actually overlapped, there is a single
    \blueite{sequential} history that explains what everyone saw.
    \begin{itemize}
      \item<2 -> Herlihy \& Wing gave this a name in 1990
    \end{itemize}
  }
  \frame{
    \frametitle{Lining up}
    \begin{center}\linearization[aside]\end{center}
  }
  \frame{
    \frametitle{The catch}
    A block runs \blueite{as if} it were alone\dots
    \begin{itemize}
      \item<2 -> \dots and only finds out at the end whether it actually was
    \end{itemize}
  }

  \frame{\signpost{4}}

  \frame{
    \frametitle{Step one}
    \begin{center}\txlog\end{center}
  }
  \frame{
    \frametitle{Step two}
    At the end of the block, check the log against the world:
    \begin{enumerate}
      \item<2 -> everything I read is still what I read? \blueite{Commit}:
                 write the log out, all at once
      \item<3 -> something changed under me? \blueite{Throw the log away}
                 and run the block again
    \end{enumerate}
  }
  \frame{
    \frametitle{Validate, then commit}
    \begin{center}\scalebox{0.9}{\stmlog}\end{center}
  }
  \frame{
    \frametitle{Optimism}
    Locks are pessimistic: pay up front, every time.
    \begin{itemize}
      \item<2 -> Transactions are optimistic: pay only on a conflict, and
                 then by \blueite{retrying}
      \item<3 -> This is \blueite{software} transactional memory, and you can
                 build it in a library
    \end{itemize}
  }
  \frame{
    \frametitle{Relate back to data structures}
    Two atomic blocks that touch \emph{different} nodes of the tree never
    hear about each other.
    \begin{itemize}
      \item<2 -> Fine-grained parallelism, without fine-grained locks
      \item<3 -> Same node? One of them retries, and nobody deadlocks
    \end{itemize}
  }

%%% Thirty years later
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

  \frame{\signpost{5}}

  \frame{
    \frametitle{In hardware}
    \begin{enumerate}
      \item<2 -> Sun's Rock was going to ship it. Rock was cancelled.
      \item<3 -> IBM shipped it in Blue Gene/Q and POWER8
      \item<4 -> Intel shipped it as TSX in Haswell (2013)\dots
      \item<5 -> \dots then disabled it by microcode. Twice.
    \end{enumerate}
  }
  \frame{
    \frametitle{In software}
    \begin{enumerate}
      \item<2 -> Software transactional memory: same promise, no new
                 instructions
      \item<3 -> Haskell's \texttt{STM} (Harris, Marlow, Peyton Jones,
                 Herlihy, 2005)
      \item<4 -> Clojure's refs, and a long tail of libraries for everything
                 else
    \end{enumerate}
  }
  \frame{
    \frametitle{So why isn't it everywhere?}
    \begin{enumerate}
      \item<2 -> Capacity: a block that touches too much \blueite{always}
                 aborts
      \item<3 -> Side effects: you can't un-\texttt{print} inside a retry
      \item<4 -> Overhead: software versions pay on every access, conflict
                 or not
      \item<5 -> Hardware versions turned out to be a side channel
    \end{enumerate}
  }
  \frame{
    \frametitle{Mind the gap}
    The \blueite{interface} aged beautifully. The \blueite{implementations}
    keep getting un-shipped.
  }
